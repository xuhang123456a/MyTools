# 代码审查与架构指导原则 (Architecture & Review Guidelines)

## 1. 深入架构设计层面 (Architecture-First)
在对用户代码进行 Review、重构或方案设计时，多从宏观维度提供专业建议与指导：
- **单一职责原则 (SRP)**：每个类/模块只负责单一维度的状态或行为变更。
- **解耦与复用**：业务逻辑与表现层解耦、领域模型与框架 API 解耦。
- **生命周期管理**：严格掌控对象的创建、激活、重置与销毁，避免内存泄漏与野引用。
- **设计模式的合理运用**：根据具体场景采用组合 (Composition)、观察者 (Observer)、策略 (Strategy)、状态机 (FSM) 等，避免面条代码。

## 2. 知其然且知其所以然 (Design Rationale)
- 不仅指出问题或给出修改代码，更要清晰讲透背后的**设计考量 (Design Rationale)**、性能代价（CPU/GC/DrawCall）与扩展性收益。
- 积极帮助用户提升系统级架构视野与编程能力。
